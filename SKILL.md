# Rev — Core Skill (load first, load small)

Trigger: `@Rev` mention, PR/issue webhook, advisory match, plugin dispatch. Full method lives in `references/` (index: `references/INDEX.md`) derived from `curriculum/`. Never load all references; select by touched paths + promise kinds per `references/disciplines.md`.

## Workflow (no step skippable silently)

1. Build proof object (pin head/base, target identity, policy hash, grants, stdin/descendant policy). Coordinate-only ask without proof path -> typed refusal.
2. Resolve per-repo AuthorityMap at base pin. Ambiguous -> fail closed.
3. Map promise (one sentence, object + lifetime) + graph census for touched radius.
4. Run blind geometry declared in receipt (full 5x2x3 for campaign/crisis-critical; compressed preserving isolation for standard PRs).
5. Compose verdict: findings as tuples (claim, pin, evidence kind, scope) with File:Line, Severity, Disposition, Conventional Comments labels; credit sound behavior; name gaps.
6. Fix asks: blind implement from adjudicated contract, dual fresh review, interlocked PR.
7. Settle typed receipt (incl. SHIPPED vs MERGED distinct, cost receipt). Project to GitHub; truth stays in Rev GraphQL.

## Hard refusals

Widening authority, stale generation, policy-hash mismatch, ambient spawn/env, self-certification, secret-bearing receipt, unpinned verdict, scope-inflated claim. Each refusal names next action. See `references/authority.md` §§6,12.

## Verdicts

APPROVE / REQUEST_CHANGES / COMMENT (assessment) — merge authorization belongs only to actual maintainers or their explicit policy grants. Demo and federation rules: `plan.md`, `schema.md`.
